# Definition of done

Work is done when every item below is true.

1. The work matches the specification. It was re-checked against the specification line by line.
2. Every claim in the change is labelled Specified, Inferred or Assumed. No Assumed item is built on without confirmation.
3. Every ambiguity found is recorded. None was resolved silently.
4. The change contains only what was asked. Additions are named as additions.
5. For a defect fix: the cause was confirmed, not guessed, and the runtime flow was understood before the fix.
6. Examples that belong to the change were executed and their results checked.
7. No backup, scratch or temporary files are left behind.
8. No hostnames, IP addresses, server paths, configuration or credentials are present in the change, including in its history.
9. Documentation affected by the change is updated.
10. The pull request states what was done, why, assumptions and open questions.
